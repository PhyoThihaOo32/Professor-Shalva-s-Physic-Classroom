# Live conversations and revised work

Settings accepts a personal OpenAI API key and model. The secret is encrypted with AES-256-GCM and owner-bound authenticated data, using a key derived from the server secret (`AI_KEY_ENCRYPTION_SECRET` if configured, otherwise `GUEST_COOKIE_SECRET`). Only ciphertext is persisted in `AiConnection`; its guest/user foreign keys cascade on identity deletion. Status, config, sessions, logs, and history exports never include the key. The password field is cleared after save and never repopulated. There is no localStorage/sessionStorage credential copy. Disconnect deletes the personal connection.

Saving does not call OpenAI. The separate Test connection action checks model access through the server using `models.retrieve`, with no generated completion. This confirms key/model access, not billing, structured-output support, or the correctness of future physics. The existing shared environment connection remains supported. Personal credentials authorize only their owner's sessions.

An active classroom connects to Live OpenAI on opening when its owner has a configured key. The ownership/revision/idempotency protected provider switch makes no model call and retains existing discussion and work. The live classroom has no provider selector or message-purpose buttons; every message is conversation. Model/key settings remain on the Settings page. Failed live calls never substitute canned demo replies. Manual practice stays in mock mode and uses its own independent correction tools.

The conversation model receives the public question and current visible step as background context. The last six discussion exchanges are sent as separate teacher (user) and student (assistant) turns, with the latest teacher message last. Trusted character instructions are separate from conversation data. It may answer naturally, calculate, explain an alternative method, or revise the current step in response to teacher guidance. Structured output contains `message` and a nullable `work` replacement. Stable step IDs, field limits, and private-metadata restrictions are validated; invalid output gets at most one repair. Numbers and equations are permitted. A missing figure remains missing rather than being fabricated. The model has no private solution, error plan, tools, or code execution. See [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) and [server-side API-key guidance](https://developers.openai.com/api/reference/overview).

A guide-message rewrite is saved atomically with its conversation event and operation result. The original authored guide stays intact in saved data and Manual practice, the old current work enters revision history, and affected checks and root assessments are reopened or marked provisional. Generated work remains a student draft. Teacher corrections still use the independent physics evaluator and original question's reviewed reference. After an accepted correction, live student work and reactions can be generated separately; their new draft remains pending a check. Hypothetical numbers do not redefine the graded problem's reference. The initial approved attempt and later guide steps remain authored for now, as requested. Custom published problems still use the existing owner content workflow.

`store:false`, strict output schemas, zero SDK retries, the shared 30-second operation deadline, and existing session/call/spending caps remain in use. Key connection testing uses a separate ten-second timeout. No paid calls are needed for UI or transport-stub verification.

The composer sends with Enter and inserts a newline with Shift+Enter; the shortcut remains functional without a visible hint. Cmd/Ctrl+Enter remains supported. Empty messages, held-key repeats, and Enter during IME composition do not submit. Bart’s live conversation uses a separate trusted developer instruction for a casual, mischievous, shortcut-loving schoolkid voice. Greetings stay conversational; calculation and correction requests still require substantive work. This character instruction never reaches the independent physics evaluator or other students. See [prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering).

Live work equations are parsed by KaTeX before acceptance. Incomplete or invalid LaTeX triggers the existing single bounded repair rather than being saved as a broken display. Prompt instructions keep explanations in plain text and equations concise within the existing field limits. This format check does not certify mathematical correctness; revisions still await an independent physics check.

Conversation and board text also render bracketed LaTeX with the existing KaTeX renderer, including older saved drafts that contain display-math wrappers. Literal text remains escaped and KaTeX trust stays disabled.

The compact classroom header shows the student and problem once. Its expandable board displays revised student work, excludes unchanged authored steps and the original guide from history, and keeps all manual next/check/hint tools in Library → Manual. Manual sessions carry an owner-bound, persistent session-event marker exposed as a public mode flag, so progress-based classroom recovery excludes them even when the local classroom preference is missing. No database migration is required.
